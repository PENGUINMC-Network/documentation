Section 1

Penguin Bot

Discord bot for Penguin Network — giveaways, tickets, verification, welcome cards, temp voice, suggestions, and utilities.

Penguin Bot

Features

The bot is organized around modular systems, each with commands, handlers, and persistent state where needed.

🎁

Giveaways

Create, edit, pause, resume, reroll, and cancel giveaways. Supports role requirements, account/server age checks, custom emoji, and persistent recovery after restart.

🎫

Ticket System

Category-based ticket creation, staff dashboard, claim/unclaim, priority, notes, tags, user add/remove, auto-close, and online HTML transcripts.

🔐

CAPTCHA Verification

Persistent verification panel with a generated CAPTCHA image and modal answer flow. Successful users receive the configured verified role.

👋

Welcome Cards

Canvas-generated welcome images with configurable background, accent colors, text, buttons, embeds, and test/preview commands.

🔊

Temporary Voice

Join-to-create voice hub that spawns private rooms with a dashboard for rename, limit, lock/hide, permit, kick, transfer ownership, and cleanup.

💡

Suggestions & Utilities

Suggestion submission with approve/reject/implement flow, Minecraft server status detection, and staff/admin utility commands.

Penguin Bot

Penguin Bot

Setup

Install dependencies, configure environment variables, deploy commands, and start the bot.

1

Install dependencies

Install Node dependencies in the bot project.

bash
npm install
2

Create .env

Add your Discord credentials and transcript server settings.

.env
DISCORD_TOKEN=your_bot_token_here
CLIENT_ID=your_client_id_here
GUILD_ID=your_guild_id_optional_for_dev

TRANSCRIPT_PORT=25634
TRANSCRIPT_PUBLIC_URL=http://localhost:25634
3

Build and deploy commands

Compile TypeScript and register slash commands.

bash
npm run build
npm run deploy
4

Start the bot

Run the compiled bot from dist/.

bash
npm start

Penguin Bot

Configuration

Penguin Bot uses .env for secrets, config.json for general settings, and YAML files in dist/config or config for feature modules.

Environment Variables

VariableRequiredDescription
DISCORD_TOKENYesBot token. DISCORD_BOT_TOKEN also supported.
CLIENT_IDDeployApplication/client ID. Deploy script can resolve it from token.
GUILD_IDNoOptional guild for instant command deployment during development.
TRANSCRIPT_PORTNoPort for transcript web server. Default 25568.
TRANSCRIPT_PUBLIC_URLNoPublic base URL used in transcript links.

Configuration Files

  • config.json — Bot name, colors, giveaway defaults, staff fallback, storage path, Minecraft default server.
  • dist/config/ticket.yml — Ticket categories, channels, roles, auto-close, panel text, storage paths.
  • dist/config/welcome.yml — Welcome channel, message/embed, card design, buttons.
  • dist/config/verify.yml — Verification channel, verified role, CAPTCHA panel and timeout settings.
  • dist/data/*.yml/json — Runtime data: giveaways, closed tickets, transcripts, temp voice state.
Security note: Never commit .env or bot tokens. The real bot workspace contains a .env; keep secrets local and use placeholders in docs and examples.

Penguin Bot

Systems

How the major modules behave at runtime.

🎁 Giveaway System

Managed by GiveawayManager with local YAML persistence.

  • Stores giveaways in dist/data/giveaways.yml (configurable).
  • Supports requirements: required/blacklisted roles, min account age, min server age.
  • Recovers active giveaways on startup and ends missed giveaways.
  • Button-based entry toggling with ephemeral feedback.

🎫 Ticket System

Implemented by TicketSystem, TicketStorage, and TranscriptServer.

  • Category modal creates a private ticket channel with permission overwrites.
  • Staff controls: claim, notify, rename, priority, notes, tags, add/remove users.
  • Closed tickets move to closed category/name and generate HTML transcripts.
  • Transcript server exposes /transcripts/:id and /manage/:userId/transcripts.

🔐 Verification System

VerifySystem provides CAPTCHA-based role gating.

  • Posts a persistent Verify button in the configured channel.
  • Generates a canvas CAPTCHA image and stores pending code per user.
  • Modal submission validates answer and grants configured role.
  • Pending CAPTCHA expires automatically after timeout.

👋 Welcome System

Uses guildMemberAdd, welcomeConfigLoader, and Canvas image generation.

  • Sends welcome message/card on member join when enabled.
  • Supports embed title/description placeholders, buttons, and join/member fields.
  • /welcome test and /welcome preview help admins validate design.
  • Config reloads from disk without code changes.

🔊 Temp Voice System

TempVoiceSystem manages join-to-create voice channels.

  • Joining hub creates a private room and moves the member.
  • Dashboard controls: rename, limit, lock, hide, delete, kick, permit, transfer.
  • Owner leaving or empty room triggers cleanup.
  • State persists in dist/data/temp-voice.json and recovers on restart.

🧰 Utilities

Support features used across systems.

  • Minecraft status: detects IP/domain or ip trigger and replies with Java/Bedrock ping embed.
  • Suggestions: posts to configured suggestion channel with vote reactions and staff status updates.
  • Permissions: centralized staff/admin checks for giveaway and ticket actions.
  • Safety: unhandled rejection/exception logging and graceful shutdown handlers.

TPA PhantomMC Plugin

Minecraft Spigot/Paper plugin for teleport requests between players. Source: TPA-Plugin-main.

TPA Plugin

Overview

Core plugin information and build stack.

Plugin Details

  • Name: TPAPlugin
  • Package: org.abbas.tPAPlugin
  • Platform: Spigot/Paper, api-version: 1.21
  • Java: 21
  • Build: Maven + Shade + ProGuard
  • Database: SQLite (database.db)
GitHub: PENGUINMC-Network/TPA-Plugin

Main Components

  • Managers: TPARequestManager, TeleportManager, CooldownManager, PlayerToggleManager.
  • Services: TPARequestService, DatabaseService, SqliteService.
  • Listeners: move/damage/quit listeners cancel or clean up teleports/requests.
  • Config: ConfigManager and MessageManager for settings and messages.

  file: database.db

Messages

Messages are configurable with placeholders like %player% and %seconds%. Includes request sent/received/accepted/denied/expired/cancelled, teleport warmup/success/cancel, toggle, cooldown, and permission errors.

Action bar: teleport-actionbar and teleport-actionbar-success show teleport countdown/status.

TPA Plugin

Runtime Behavior

How requests and teleports are handled.

Request Lifecycle

  • Requests are stored with sender, target, type, creation, and expiry time.
  • Expired requests are removed by scheduler and both players are notified.
  • Outgoing requests can be cancelled; quit handling cleans related requests/teleports.

Teleport Safety

  • Accepted requests start a warmup countdown (action bar).
  • Movement or damage can cancel warmup depending on config.
  • Teleport tasks and action bars are cleaned up on shutdown.
  • SQLite database is initialized on enable and closed on disable.

Architecture

High-level project layout from the bot-with-verification source.

bot-with-verification/
├── index.ts                     # Bot bootstrap, client, managers, command/event loading
├── config.json                  # General bot/giveaway/minecraft settings
├── dist/config/                 # Runtime YAML configs (ticket/welcome/verify)

├── src/
│   ├── commands/                # Slash command modules
│   ├── events/                  # ready, interactionCreate, guildMemberAdd, messageCreate...
│   ├── handlers/                # Button/modal legacy handlers
│   ├── structures/              # GiveawayManager, TicketSystem, VerifySystem, Storage...
│   ├── temp-voice-channel/      # Temp voice system, dashboard, store
│   └── utils/                   # embeds, permissions, time, config loaders, canvas utils
└── assets/                      # Fonts and images used by Canvas cards/CAPTCHA
Runtime flow: index.ts creates the Discord client, loads commands/events, initializes managers, and logs in. ready restores state, starts transcript server, sets timers, and recovers temp voice. interactionCreate routes slash commands, autocomplete, buttons, selects, and modals to the appropriate system.

Operations

Deployment

Recommended practices for running Penguin Bot in production.

Production Checklist

  • Set production DISCORD_TOKEN and remove GUILD_ID for global commands if desired.
  • Configure transcript public URL/port and open firewall/reverse proxy as needed.
  • Ensure bot has required Discord permissions: Manage Channels/Roles, Send Messages, Embed Links, Attach Files, Move Members, etc.
  • Place bot role above verified/ticket-managed roles where role assignment is needed.
  • Persist dist/data and config files across restarts/deployments.

Build & Run

bash
npm ci
npm run build
npm run deploy
npm start

Use a process manager like PM2, systemd, or Docker for auto-restart and logs. Keep dist/data writable.

Help

Troubleshooting

Common issues and where to look first.

Commands not appearing

Run npm run deploy. For instant guild updates set GUILD_ID. Global commands can take time to propagate. Confirm the bot logged in and deployment logged success.

Verification role not assigned

Check /verify settings, ensure role ID is valid, and move the bot role above the verified role. The bot needs Manage Roles permission.

Ticket transcript links broken

Verify TRANSCRIPT_PUBLIC_URL and TRANSCRIPT_PORT. Ensure TranscriptServer started and the port is reachable. Check SSL/file permissions if using HTTPS cert paths.

Welcome/CAPTCHA image fails

Confirm @napi-rs/canvas installed correctly and font/assets files exist. Check logs for font registration or image generation errors.

Temp voice room not created

Bot needs Manage Channels, Manage Roles, Move Members, Connect, and View Channel. Re-run /tempvoice setup and ensure hub is a voice channel.

Data not persisting

Check write permissions for dist/data and configured storage paths. Avoid deleting runtime files during deploy; back them up before updates.
